→ renderTarget-viewport 를 짝지어서 관리가 필요할 것

- **디퍼드 셰이딩을 도입한 이상, 논리적으로 GPass는 기존 MainPass와 같다**

→ GPass전용 Shader들을 따로 만들 필요가 있을까?

→ 기존 Command들을 최대한 두도록 할 수는 없을까?

→ 결국, 기존의 MainPass가 GPass가 아닌가? 이 사실을 어떻게 이용할까?

1. 따라서 아래와 같이 수정
2. 기존 MainPass 열거형을 Renderer 내부에서 GPass로 사용한다.
3. 기존 GPass로 추가한 RenderPass는 Deferred 로 변경한다.
    1. 병합 및 라이팅 계산을 하는 진짜 MainPass.
    2. 사용자 입장에서 명확하게 기존처럼 MainPass로 제공한다.
    3. Deferred Pass는 Renderer가 내부적으로 command를 생성한다.(딱 하나)
4. RenderPass-RenderTarget 매핑 테이블을 수정
    1. Main Pass에 해당하는 렌더타겟을 GBuffer로 바인드하고,  
        Deferred Pass에 해당하는 렌더타겟을 기존에 쓰던 Default로 설정한다.

- **Deferred Pass를 실수로 추가하게 되면? 이를 방지할 방법이 있을지?**

→ renderer가 deferred pass 에 대한 command를 생성하기 전에, object들을 순회하면서 commandList를 구성하니, 이를 활용한다.

먼저 commandList를 순회하면서 deferred Pass와 같은 renderer 전용 pass를 사용한 object들이 있는지 검사하여 있다면, assertion을 건다.

없다면, 문제 없이 deferred pass command를 생성하여 list에 추가한다.

이 체크는 debug 빌드에서만 돌린다.

### 최종 내용

- **09.03) Deferred Rendering 설계 1 - Main을 GPass로 사용**

1. 외부에서는 기존과 동일하게 `Main`으로 Render Command를 제출한다.
2. Main 패스는 GBuffer 전용 MRT를 직접 바인딩한다.
3. 별도의 GPass Command 변환 및 복사 과정은 두지 않는다.
4. 기존 Main 셰이더는 라이팅을 제거하고 GBuffer 데이터를 출력하도록 변경한다.
5. 최종 라이팅 및 병합 패스는 Renderer가 Command를 직접 생성한다.
6. Renderer 전용 Command가 외부에서 사용되지 않도록 검증 로직을 수행 한다.

- **RenderPass들을 다른 물체들이 오용할 가능성 처리**

1. 렌더러가 Deferred Pass 제출하기 전에 object들이 제출한 command들을 검사하여 오용된게 있는지 검사한다.
    1. ex)현재는 DeferredPass뿐이므로 이게 검출되면 assertion.

- **09.04~06) Deferred Rendering 설계 2 -Lighting을 위한 RT 설계**

1. Lighting을 하기 위해 고민 결과, 아래와 같이 RT를 추가하였음.
    1. 기존: GColor, GNormal, GDepth
    2. 변경: GColor, GNormal, GPosition, GSpecular, GAmbient
        1. 이때, GNormal, GPosition은 world-space
        2. GPosition의 w에는 Lighting을 할지 말지 플래그를 담음(1,0) - IsLitOn
        3. 나머지 w는 Reserved
2. world-space 통일에 대해서
    1. 기존 normal texture의 내용물이 어떻게 인코딩되었는지, 공간이 어딘지 파악할 수 없어서 이참에 제거하고 직접 attribute로부터 가져와 계산하도록 바꿈.
    2. 이때 world-space로 통일하여 normal과 position을 PS로 넘겨주기로 결정
3. Lighting여부 플래그(IsLitOn)은 모든 Mesh는 하나의 SubMesh를 무조건 가지고, SubMesh는 SemiMaterial을 가짐.
    1. 따라서 MaterialFactor가 가지고 있는 reserved 공간을 활용하면 되지 않을까하여 MaterialFactor에 포함하도록 함

- **09.07) Deferred Rendering 설계 3 - 그림자 연결**

1. CB에 대한 Renderer 예약 슬롯이 VS를 기준으로만 설계되어 있는 문제.
    1. VS에서 PsInput으로 요소들을 넘겨주는 방법 적용.
    2. vs,ps 양쪽 바인드보다 좀 더 유연한 시스템 설계 지향을 위해 고민을 먼저 하고 구조 개선.
2. 그림자 색상을 뭘로 할지?
    1. 임의로 정한 값으로 사용하니, 그림자와 라이팅 받는 부분이 만나는 지점이 색이 어색함.
    2. 이런저런 값을 넣어보다가 ambient색상을 넣어봤을 때 가장 자연스럽게 이어짐을 확인
