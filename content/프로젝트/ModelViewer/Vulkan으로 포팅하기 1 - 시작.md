### 개요

지금까지 D3D11을 사용하여 간단한 모델 뷰어를 만들어왔으나, 최근 차세대 API라고 부르는 API들도 현시점 10년이 지나가고 있고, 이제는 모두가 사용하는 수준으로 보았습니다.

apple의 경우는 metal api로 전환하여 opengl 지원을 종료한지 한참 되었고, android의 경우
vulkan을 기본 레이어로 깔고 있고, opengl도 ANGLE로만 지원하겠다는 로드맵이 있었습니다.

속으로 공부를 잘못했구나 싶었지만 어쨌든 과거에 잘못 판단한 것들 되돌릴 수는 없고, 
여기서 더 뒤처질 수는 없다고 생각했기 때문에 차세대 API로 넘어가기로 했습니다.
(나름 자기위안을 하면 그래도 D3D11을 했던 경험을 살려서 Vulkan 기본 개념은 쉽게 접근할 수 있었습니다.)

개인적으로는 D3D12를 더 선호하지만, 이상과 현실은 항상 달랐다는 점..
아무래도 실무에서는 멀티플랫폼을 지원해야 하는 경우가 많기 때문에 고민 끝에 Vulkan을 선택하기로 했습니다.


#### 버전 선택
그다음으로는 어떤 버전을 고를까 고민해 봤을 때, 

아무래도 전에 한 실수를 또 반복할 수 없기 때문에 1.0, 1.1버전 같은 레거시 기준으로 배울 필요는 없었고,

1.3 버전에 추가된 DynamicRendering 처럼 1.3버전이 마치 모던 GL처럼 꽤 큰 기능들이 들어온 
버전으로 보였기 때문에 최소 1.3을 선택할 필요는 있어 보였습니다.

마지막으로 최근에는 현 차세대 API들도 너무 구 방식에 의존하고 있다는 지적에 따라 bindless 방식으로 진화하고 있는 움직임이 보였습니다.([no graphics api](https://community.arm.com/cfs-file/__key/communityserver-blogs-components-weblogfiles/00-00-00-20-66/6763.2026_2D00_mmg_2D00_seb_2D00_gfx_2D00_api.pdf))

종합하여 최신 버전인 1.4버전을 골랐습니다.

특히 놀랐던 점은 크로노스에서 공식 튜토리얼을 제공하는데, 매우 상세하고, 여러 기능들에 대한 
튜토리얼을 제공한다는 점.(그리고 튜토리얼이 1.4버전을 기준으로 합니다.)


#### C API or RAII
여기에서 차이점은 튜토리얼은 RAII 방식으로 소개하는데, 제 경우에는 C API를 기준으로 학습하고 포팅 하기로 했습니다. 
이미 현업에서는 C API 방식으로 쓰고 있을 것이기 때문이기도 하지만, 렌더링 엔진은 보통 API를 한번 래핑 하기 때문에 RAII를 굳이 안 써도 되겠다 싶은 생각입니다.


#### **작업 범위**
작업 범위는 D3D11로 디퍼드 렌더링까지 구현했기 때문에 vulkan 포팅의 최종 목표도 디퍼드렌더링을 구현하는 것까지를 범위로 잡았습니다.



### 개발 환경

Vulkan 1.4, SDK 1.4.357
GLFW, SDL 같은 라이브러리는 이용하지 않고 기존 프로젝트에서 사용하던 win32를 사용하여 윈도우와 연결합니다.
입력 라이브러리도 기존에 구축했던 xinput 라이브러리를 그대로 사용합니다.


따로 튜토리얼처럼 하나하나 따라 하거나 진행하는 과정을 나열하지 않을 예정이고,
진행하면서 공유할 만한 정보들만 간략하게 업로드될 것입니다.
